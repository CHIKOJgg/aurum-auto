# Aurum Research Club → MetaTrader 5

Локальный Windows-бот читает подписи новых постов одного Telegram-канала через
личную Telegram-сессию и независимо исполняет разрешённые сигналы на любом
количестве терминалов MT5.

> Сначала используйте только демо-счёт. Автоматическая торговля несёт риск:
> комиссия, проскальзывание и гэпы могут сделать фактический убыток больше
> номинального расчёта 1%.

## Зафиксированная логика

- Канал: `Aurum Research Club`, ID `3978977082`.
- Новые сообщения принимаются сразу через Telegram `NewMessage` updates без
  периодического опроса. Бот не отправляет сообщения и не скачивает картинки.
  Текст поста с картинкой читается как обычная подпись.
- На каждом запуске все сообщения, появившиеся до момента запуска, считаются
  устаревшими. Старые коллы никогда не исполняются.
- Каждый новый `message_id` сначала атомарно фиксируется в `runtime/state.json`,
  поэтому редакции и повторная обработка игнорируются.
- Поддерживаются `XAUUSD`, `XAGUSD`, `DE40`, `US100` и шестибуквенные валютные
  пары. Посты о TP/SL игнорируются.
- Коллы могут использовать названия FxPro: `#GOLD`, `#SILVER`, `#Germany40` и
  `#USNDAQ100`. Для обратной совместимости также поддерживаются прежние теги
  `#XAUUSD`, `#XAGUSD`, `#DE40` и `#US100` соответственно.
- Используются цена входа, SL, все четыре тейка и выбранная в
  `trading.exit_strategy` стратегия выхода (по умолчанию `sl_tp2`).
- LONG и SHORT: если расчётный риск до SL находится в закрытом диапазоне
  `0,9R–1,1R`, используется рыночный вход. Равная цене колла цена (`1R`) и обе
  границы диапазона входят по рынку. При риске ниже `0,9R` или выше `1,1R`
  выставляется лимитка по цене колла.
- Отклонённая брокером лимитка заменяется рыночным ордером только если
  обновлённая цена попала в диапазон `0,9R–1,1R`.
- Отложенные заявки — GTC, без срока истечения. Достижение или пересечение
  ценой SL либо выбранного TP не отменяет заявку.
- Если текущая цена в момент колла уже пересекла SL или выбранный TP, сигнал не
  пропускается: выставляется отложенная заявка по цене входа из колла. Когда
  обычный лимитный тип невозможен из-за положения цены за SL, MT5 получает
  стоп-заявку на той же цене входа.
- Режим счёта определяется автоматически. В hedging существующие позиции и
  отложенные заявки сохраняются. В netting/exchange перед новым коллом бот
  снимает все pending-ордера этого инструмента, закрывает его текущую позицию и
  отправляет новый колл только после подтверждения, что инструмент очищен.
- В hedging каждый новый колл обрабатывается независимо, даже если по
  инструменту уже существуют позиции или отложенные заявки.
- В hedging старые LIMIT/BUY_STOP/SELL_STOP не отменяются новым коллом; в
  netting/exchange они снимаются при следующем колле того же инструмента.
- Ни одна позиция не открывается без точных SL и выбранного TP. Бот не расширяет уровни.
- Коллы с картинкой называются «Индюк 1» и всегда отправляются в MT5.
- Коллы без картинки называются «Индюк 2». Они всегда сохраняются в архив и
  отправляются в MT5, только если включён `trading.enable_indicator_2`.
- Бэктесты Индюка 1 и Индюка 2 разделяются флагами `--image-filter with` и
  `--image-filter without`.
- Номинальный риск каждой сделки — 1% от изменяемой фиксированной базы счёта.
  Объём рассчитывается средствами MT5 в валюте счёта и математически округляется
  до ближайших `0.01` лота: `0.0187 → 0.02`, `0.109 → 0.11`. Расчёт ниже
  `0.01` становится `0.01`. Поэтому фактический номинальный риск после округления
  вверх или применения минимального лота может быть выше исходного расчёта 1%.
  Диапазон `0,9R–1,1R` проверяется по теоретическому объёму до округления.
  Например, при расчёте `0.0187` порог проверяется для `0.0187`, а в MT5 затем
  отправляется `0.02`.
- Все включённые счета исполняются в отдельных процессах. Сбой одного счёта не
  отменяет и не блокирует остальные.
- Одновременно может работать только один экземпляр бота.

## 1. Установка Python

Установите актуальный 64-битный Python для Windows с
[python.org](https://www.python.org/downloads/windows/) и включите опцию
`Add python.exe to PATH`.

В PowerShell из папки проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
```

## 2. Telegram API

1. Войдите на [my.telegram.org](https://my.telegram.org).
2. Откройте `API development tools` и создайте приложение.
3. Скопируйте шаблон:

```powershell
Copy-Item .env.example .env
```

4. Заполните в `.env` свои `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и телефон.

При первом запуске Telethon запросит код Telegram и, если включена, 2FA-пароль.
После этого авторизация хранится в `runtime/telegram_user.session`.

Файл `.session` фактически даёт доступ к Telegram-сессии. Не отправляйте его
никому, не синхронизируйте в публичное облако и не добавляйте в Git. `.env`,
`runtime/` и файлы сессий уже внесены в `.gitignore`.

## 3. Терминал FxPro MT5

1. Скачайте MT5 только с официального сайта/кабинета FxPro.
2. Установите терминал в отдельную папку.
3. Войдите вручную в демо-счёт.
4. Включите алгоритмическую торговлю в терминале.
5. Проверьте точные названия инструментов в `Market Watch`. Для текущего
   шаблона используются `GOLD` и `#Germany40`; если FxPro показывает суффикс или
   другое имя, измените mapping в конфиге.

Для каждого дополнительного счёта нужен отдельный установленный и
авторизованный терминал с собственным путём к `terminal64.exe`. Торговые пароли
в конфиг не записываются.

## 4. Конфигурация

```powershell
Copy-Item config.example.yaml config.yaml
```

В `config.yaml` укажите реальный `terminal_path`. Начальная конфигурация:

- `fxpro_demo`: включён, база риска `$510`;
- `secondary_demo`: выключен, база риска `$25 000`.

Выбор стратегии выхода для live-ордеров:

```yaml
trading:
  exit_strategy: "sl_tp2"
  strict_call_entry: true  # По умолчанию только отложенный ордер строго по ТВХ
  enable_indicator_2: false  # true = исполнять коллы без картинки
```

`strict_call_entry: true` включает строгий вход по ТВХ. В этом режиме бот
никогда не входит по рынку и не делает fallback в рынок после отказа брокера:
он оставляет заявку по цене входа из колла как `BUY_LIMIT`, `SELL_LIMIT`,
`BUY_STOP` или `SELL_STOP` — в зависимости от направления и текущей цены.

При `strict_call_entry: false` бот входит по рынку, пока стоп-риск в пределах
0.9R–1.1R. Чтобы не упускать вход из-за небольшого ухода цены (например, из-за
округления лота, из-за которого фактический риск чуть больше 1.1R), добавлен
допуск по цене:

```yaml
trading:
  # Рынок, если котировка в пределах 0.25 от дистанции стопа (R) от цены колла.
  market_entry_tolerance_r: 0.25
  # Отменить неисполненный отложенный ордер через 15 минут после установки.
  pending_timeout_minutes: 15
```

`market_entry_tolerance_r` не отменяет защиту геометрии: вход по рынку возможен
только пока цена строго между SL и TP. `pending_timeout_minutes: 0` отключает
автоотмену (ордера висят бессрочно, как раньше).

### Защитные фильтры входа

```yaml
trading:
  # Пропустить вход, если спред шире 50 пунктов (GOLD: 0.50). 0 = выключено.
  max_spread_points: 50
  # Пропустить вход за 10 минут до и 15 минут после события из файла.
  news_events_file: "runtime/news_events.json"
  news_window_before_minutes: 10
  news_window_after_minutes: 15
```

Формат файла событий (UTC):

```json
[
  {"start_utc": "2026-08-12T18:00", "title": "CPI USA"},
  {"start_utc": "2026-08-13T18:00", "title": "FOMC"}
]
```

Оба окна `0` отключают новостной фильтр. Проверка маржи выполняется всегда:
если для объёма не хватает свободной маржи, вход отклоняется с явной причиной.
Результаты фильтров попадают в лог как `skipped_wide_spread` / `skipped_news`.

Значение меняется только между запусками: после правки YAML перезапустите бота.
Уже открытые позиции продолжают сопровождаться по стратегии, сохранённой при
их открытии. Для любой стратегии колл должен содержать TP1–TP4, иначе он будет
проигнорирован.

### Стратегии выхода

Чтобы выбрать вариант, скопируйте его ID из первого столбца в
`trading.exit_strategy`. Например, лидер бэктеста:

```yaml
trading:
  exit_strategy: "market_tp2_pending_tp4"
  strict_call_entry: false
```

При `strict_call_entry: true` все входы являются отложенными, поэтому
`market_tp2_pending_tp4` всегда выберет TP4. Для разделения MARKET и
LIMIT/STOP, как в бэктесте, нужен `strict_call_entry: false`.

Доступны все 40 протестированных правил. У них 39 уникальных результатов:
сессионный вариант на этой выборке совпал с полным TP4, но в YAML он оставлен
отдельным вариантом.

| ID в YAML | Правило |
|---|---|
| `market_tp2_pending_tp4` | MARKET закрывается на TP2, LIMIT/STOP — на TP4 |
| `tp4_soft_staircase` | TP4; после TP2 SL в Б/У, после TP3 SL на TP1 |
| `tp4_be_after_tp2` | TP4; после TP2 SL в Б/У |
| `sl_tp4` | Весь объём на TP4 |
| `tp2_50_tp4_50` | 50% на TP2, остаток на TP4 |
| `tp2_50_tp4_50_be_after_tp2` | 50% на TP2, остаток на TP4 со SL в Б/У |
| `gold_indices_tp4_forex_tp2` | XAUUSD, DE40 и US100 на TP4; остальные на TP2 |
| `tp2_60_tp4_40` | 60% на TP2, 40% на TP4 |
| `dynamic_tp3_tp4_be` | TP2 за ≤30 минут — TP4, иначе TP3; после TP2 SL в Б/У |
| `tp4_time_be_15m` | TP4; через 15 минут, если позиция в прибыли, SL в Б/У |
| `tp2_25_tp4_75` | 25% на TP2, 75% на TP4 |
| `tp2_40_tp4_60` | 40% на TP2, 60% на TP4 |
| `tp2_75_tp4_25` | 75% на TP2, 25% на TP4 |
| `tp2_80_tp4_20` | 80% на TP2, 20% на TP4 |
| `tp3_50_tp4_50` | 50% на TP3, 50% на TP4 |
| `tp3_be_after_tp2` | TP3; после TP2 SL в Б/У |
| `sl_tp2` | Весь объём на TP2 — прежняя стратегия по умолчанию |
| `tp1_tp2_tp4_thirds` | 33% на TP1, 33% на TP2, 34% на TP4 |
| `tp1_25_tp2_50_tp4_25` | 25% на TP1, 50% на TP2, 25% на TP4 |
| `tp1_tp2_tp3_tp4_equal` | По 25% на TP1, TP2, TP3 и TP4 |
| `tp1_50_tp4_50` | 50% на TP1, 50% на TP4 |

| `tp2_50_tp3_50` | 50% на TP2, 50% на TP3 |
| `tp4_exit_4h_if_no_tp1` | Закрыть по рынку через 4 часа, если TP1 не достигнут; иначе ждать TP4 |
| `tp4_time_be_120m` | TP4; через 120 минут в прибыли SL в Б/У |
| `sl_tp3` | Весь объём на TP3 |
| `tp4_time_be_30m` | TP4; через 30 минут в прибыли SL в Б/У |
| `tp4_time_be_240m` | TP4; через 240 минут в прибыли SL в Б/У |
| `tp2_33_tp4_67_lock_tp1` | 33% на TP2, 67% на TP4; после TP2 SL остатка на TP1 |
| `tp4_lock_tp1_after_tp2` | TP4; после TP2 SL на TP1 |
| `tp3_lock_tp1_after_tp2` | TP3; после TP2 SL на TP1 |
| `tp4_staircase` | TP4; после TP2 SL на TP1, после TP3 SL на TP2 |

| `tp4_be_after_tp1` | TP4; после TP1 SL в Б/У |

| `sl_tp1` | Весь объём на TP1 |
| `tp1_25_tp2_25_tp4_50_stair` | 25% TP1, 25% TP2, 50% TP4; TP1→Б/У, TP2→SL на TP1 |
| `tp3_be_after_tp1` | TP3; после TP1 SL в Б/У |
| `tp4_full_staircase` | TP4; TP1→Б/У, TP2→SL на TP1, TP3→SL на TP2 |
| `active_session_tp4_other_tp2` | 07:00–20:00 UTC на TP4, вне сессии на TP2 |

Частичные объёмы рассчитываются от исходного лота с накопительным округлением
вниз до шага брокера: неисполненная доля переносится на следующий тейк, а
последний выход получает весь остаток. Финальный TP и исходный SL всегда стоят
на сервере MT5; частичные выходы, переносы SL и временные правила сопровождает
бот каждые две секунды. Поэтому для управляемых стратегий бот должен оставаться
запущенным. После перезапуска он продолжает активные планы из
`paths.strategy_state_dir`.

Изменение базы:

```yaml
risk_base_usd: 510
```

Включение/отключение:

```yaml
enabled: true
```

Новый счёт добавляется ещё одним элементом в `accounts`. Имя должно быть
уникальным, терминал — отдельным, а mappings инструментов — точными:

```yaml
- name: "another_demo"
  enabled: false
  risk_base_usd: 10000
  terminal_path: "C:/MT5/Another/terminal64.exe"
  symbols:
    XAUUSD: "XAUUSD"
    XAGUSD: "SILVER"
    DE40: "GER30"
```

Если нужен только один счёт, у остальных поставьте `enabled: false` или удалите
их из списка.

## 5. Проверка и запуск

Сначала запустите автоматические тесты:

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Затем запустите бота:

```powershell
.\start_bot.bat
```

Также можно дважды щёлкнуть по `start_bot.bat` в Проводнике. BAT-файл проверит
наличие `.venv`, `.env` и `config.yaml`; при ошибке окно не закроется сразу.

Логи находятся в `logs/aurum_bot.log`, состояние основного канала — в
`runtime/state.json`. Если для теста меняется `channel_id`, бот автоматически
создаёт отдельный файл вида `runtime/state.<channel_id>.json` и не смешивает
историю сообщений разных каналов.
Первый запуск только фиксирует последнее сообщение канала. Для безопасного
демо-теста дождитесь нового реального колла либо опубликуйте тестовый колл в
отдельной копии канала после временной смены его ID/названия в конфиге.

Остановка: `Ctrl+C`. После перезапуска сообщения, пришедшие во время простоя,
будут отмечены устаревшими и не вызовут сделок.

## Что проверять в демо

Перед использованием реальных средств проверьте в журнале и MT5:

1. Точные broker symbol names.
2. Рассчитанный объём для обоих инструментов.
3. Направление LONG/SHORT.
4. Рынок против лимитного ордера при разных текущих ценах.
5. Точные SL и выбранный TP.
6. Замену старой лимитки новым коллом.
7. Пропуск нового колла при уже открытой позиции.
8. Поведение при закрытом рынке и минимальном допустимом лоте.
## Журнал сделок в Google Sheets

Google Sheets не обязателен для торговли. При `google_sheets.enabled: false`
бот продолжает читать сигналы и отправлять ордера, но не запускает запись журнала.
Даже при включённой интеграции ошибки авторизации, сети или таблицы записываются
в лог и не меняют торговое решение либо результат MT5.

В проект встроен шаблон для одного владельца: весь чистый P&L относится
к колонке `Моя доля P&L`.
Шаблон содержит листы `Сделки`, `Недели` и `Настройки` и автоматически считает
чистый P&L, недельный результат, капитал и результат в R.

Настройка:

1. Включите Google Sheets API в проекте Google Cloud и создайте JSON-ключ
   сервисного аккаунта.
2. Сохраните ключ как `runtime/google-service-account.json`.
3. Создайте новую полностью пустую Google-таблицу. Не указывайте здесь таблицу,
   которую нужно сохранить без изменений.
4. Откройте JSON, скопируйте `client_email` и выдайте этому адресу права
   редактора новой таблицы.
5. Укажите ID новой таблицы и включите автоматический шаблон:

   ```yaml
   google_sheets:
     enabled: true
     auto_setup: true
     spreadsheet_id: "ID_НОВОЙ_ПУСТОЙ_ТАБЛИЦЫ"
     account: "fxpro_demo"
   ```

6. Установите зависимости:
   `.venv\Scripts\python.exe -m pip install -r requirements.txt`.
7. Запустите разовую инициализацию и синхронизацию:
   `.venv\Scripts\python.exe -m aurum_bot.sheets_sync_cli --config config.yaml`.

Автоинициализация разрешена только для полностью пустой книги. Если в книге уже
есть данные, код завершит настройку ошибкой и ничего не изменит. Для существующей
таблицы используйте `auto_setup: false`.

После создания шаблона заполните в листе `Настройки` свой стартовый капитал,
стартовый `risk_base_usd` и понедельник первой недели. Формулы уже протянуты на
1000 сделок и 300 недель; при записи строки бот дополнительно восстанавливает её
формулы автоматически.

После принятия ордера MT5 бот создаёт строку и каждые
`google_sheets.sync_interval_seconds` обновляет исполненные и закрытые сделки.
Для закрытой сделки записываются фактические даты и цены входа/выхода, комиссия
вместе с брокерскими сборами, своп и валовый P&L.
